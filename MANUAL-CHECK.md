# Ручная проверка Дня 11 в браузере

Сценарий для проверки руками: открыть страницу и убедиться, что модель памяти
работает так, как обещает задание дня — три слоя хранятся раздельно, запись в
каждый идёт по явному правилу, и видно, что каждый слой даёт ответу.

Проверка идёт по порядку: шаги опираются друг на друга (задача, заведённая в
части 4, нужна в части 5). Каждый шаг устроен одинаково — **что сделать**,
**что должно получиться** и, если не сошлось, **куда смотреть**.

Время: около 25 минут. Вызовов модели: примерно 8-10, все на бесплатных моделях
Groq. Если упрётесь в минутный лимит, страница сама подождёт и повторит.

Механическая часть сценария (все шаги, кроме сравнения ответов в части 6)
прогнана на живом агенте: ожидания ниже — не предположения, а то, что
происходит на самом деле.

---

## Часть 0. Подготовка

**0.1. Окружение и ключ**

```bash
cd ~/Документы/AI-Advent-Challenge/Day-11
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # и вписать GROQ_API_KEY
```

В системе Ubuntu команды `python` нет — либо работайте внутри активированного
окружения (там `python` есть), либо везде пишите `python3`.

**0.2. Чистый старт**

Чтобы проверка началась с предсказуемого состояния, уведите прежнюю память в
сторону (если она есть):

```bash
mv memory memory-до-проверки 2>/dev/null || true
```

**0.3. Запуск**

```bash
python web.py        # внутри venv; иначе python3 web.py
```

Откройте <http://127.0.0.1:5000>. Порт в этом дне фиксированный: если он занят,
Flask напишет «Address already in use», а браузер покажет **чужой** старый
экземпляр — проверьте, кто держит порт: `ss -ltnp | grep 5000`.

- [ ] Страница открылась, заголовок «Агент миграции ГИС — модель памяти».
- [ ] Справа три карточки слоёв: «Краткосрочная», «Рабочая», «Долговременная»,
      под ними «Журнал маршрутизации».

## Часть 1. Слои существуют и лежат раздельно

**1.1. Разные хранилища, а не один файл**

Посмотрите на серую строку пути внизу каждой карточки справа.

- [ ] «Краткосрочная» → путь заканчивается на `memory/dialog.db`.
- [ ] «Рабочая» → путь-**каталог** `memory/working`.
- [ ] «Долговременная» → путь-**каталог** `memory/long/инженер`.

Три разных места хранения — это и есть требование «хранить раздельно». Если бы
слой был один, путь был бы один.

**1.2. Долговременная память уже наполнена**

- [ ] В карточке «Долговременная» счётчик показывает профиль, знания и решения,
      а ниже перечислены инварианты, ограничения (стек, БД, фронтенд) и знания
      про legacy-систему: `схема-gissys`, `схема-gisdata`,
      `контроллеры-codeigniter`, `интеграция-1с`.

Это наполнение при первом запуске: рамки проекта записаны заранее, а не
выдуманы моделью.

## Часть 2. Правило «реплика-диалога»

**2.1.** Запомните счётчик реплик в карточке «Краткосрочная» (в чистой памяти —
«0 реплик»).

**2.2.** В поле внизу чата введите вопрос и нажмите **Спросить**:

```
Что известно про схему gissys и какие таблицы в ней главные?
```

- [ ] Ответ появился в чате.
- [ ] Счётчик «Краткосрочная» вырос **на две** реплики: ваш вопрос и ответ
      агента. Обе видны списком в карточке.
- [ ] В «Журнале маршрутизации» верхняя строка — правило `реплика-диалога`,
      слой `краткосрочная`, отметка «записано».

Правило простое и не требует модели: любая реплика идёт в короткую память
дословно.

## Часть 3. Правило «явное-указание» и правило «разбор-реплики»

**3.1. Явная запись — без модели**

В карточке «Записать вручную»: слой **знания**, ключ `срок-миграции`, текст
`Перенос справочников планируется завершить до конца квартала`. Нажмите
**Записать**.

- [ ] Счётчик знаний в «Долговременной» вырос на единицу, запись видна в списке.
- [ ] В журнале появилась строка: правило `явное-указание`, слой
      `долговременная/знания`, «записано».
- [ ] Счётчик краткосрочной **не изменился**: это не реплика диалога.

Модель здесь не вызывается вовсе — запись идёт туда, куда сказано.

**3.2. Разбор свободной реплики — с моделью**

Вверху страницы «Маршрутизатор» = **авто**. Спросите в чате:

```
Учти на будущее: тайлы мы раздаём через Martin, а WMS остаётся на GeoServer.
```

- [ ] В журнале появилась строка с правилом `разбор-реплики` — с пометкой
      «записано» (если дешёвая модель уверена) или «нет» (если не уверена).
- [ ] В столбце «почему» написано, чем решение обосновано.

**3.3. Тот же текст при выключенном маршрутизаторе**

Переключите «Маршрутизатор» на **выкл** и отправьте похожую реплику:

```
Ещё учти: снэппинг на фронтенде делаем средствами OpenLayers.
```

- [ ] В журнале снова строка `разбор-реплики`, но с пометкой «нет» и причиной
      «маршрутизатор выключен»: дешёвая модель не вызывалась вовсе.
- [ ] Счётчик знаний в «Долговременной» не изменился.
- [ ] Реплика при этом в краткосрочной памяти есть — она ведь прозвучала.

Обратите внимание: отклонённая запись тоже попадает в журнал. Это сделано
нарочно — иначе не видно, что именно агент решил **не** запоминать и почему.

Это и есть «правила записи заданы явно»: одна и та же фраза при разных режимах
попадает в разные слои, и видно почему.

Верните «Маршрутизатор» в **авто**.

## Часть 4. Правило «шаг-задачи» — рабочая память

**4.1.** В карточке «Задача»: поле «Новая» → `перенос-справочников`, «Название»
→ `перенос справочников из gissys`. Нажмите **Завести**.

- [ ] Рядом с заголовком «Задача» появилось «стадия planning; дальше: execution».
- [ ] В карточке «Рабочая» справа стало «1 задач», задача видна в списке.
- [ ] Кнопка перехода показана только одна: **→ execution**. Это конечный
      автомат: из планирования можно только в исполнение.

**4.2.** Нажмите **→ execution**.

- [ ] Стадия сменилась, кнопок стало две: `validation` и `planning` (возврат на

**4.3.** В полях «Шаг задачи» / «Значение» введите `таблицы`
и `gissys.organization, gissys.pipe — переносим первыми`, нажмите
**В рабочую память**.

- [ ] В карточке «Рабочая» у задачи выросло число собранных записей.
- [ ] В журнале — правило `шаг-задачи`, слой `рабочая`, «записано».
- [ ] Долговременная память при этом не изменилась: промежуточный результат

## Часть 5. Правило «завершение-задачи» — мост в долговременную

**5.1. Сначала проверьте запрет.** Нажмите **Завершить и свернуть в решение**,
находясь в стадии `execution`.

- [ ] В чате появилось сообщение об ошибке: из execution сразу в done нельзя,
      разрешено — `validation`, `planning`.

**5.2.** Нажмите **→ validation**, затем снова **Завершить и свернуть в решение**.

- [ ] В чате появилось «Задача свёрнута в решение №…» с заголовком.
- [ ] В «Долговременной» число решений выросло на единицу, запись видна в
      списке «Решения».
- [ ] В «Рабочей» задача исчезла (стало «0 задач»): рабочая память — не архив.
- [ ] В журнале две строки правила `завершение-задачи`: запись решения и
      очистка рабочей памяти.

Это единственный штатный мост между слоями, и он тоже явный.

## Часть 6. Что каждый слой даёт ответу

Здесь проверяется главное требование дня — «как это влияет на ответы». Приём
один: задать один и тот же вопрос дважды, сняв ровно одну галочку «Читать слои».

**6.1. Долговременная память**

Задайте вопрос при всех включённых слоях:

```
На чём писать серверную часть нового сервиса и какую СУБД брать?
```

- [ ] Ответ называет Django + GeoDjango и PostgreSQL + PostGIS — то есть
      ограничения проекта из профиля.
- [ ] В блоке «Что ушло в промпт» под ответом видны строки со знаком «+» и
      бейджем `долговременная`.

Снимите галочку **долговременную** и задайте тот же вопрос.

- [ ] Ответ стал общим: варианты «на выбор», другие стеки, оговорки «зависит от».
- [ ] В трейсе строки долговременной памяти помечены «−» с пояснением, почему
      блок не включён.

**6.2. Краткосрочная память**

Верните галочку «долговременную». Спросите:

```
Продолжай. Делай следующий шаг.
```

- [ ] Ответ опирается на предыдущий вопрос — видно, что агент помнит разговор.

Снимите галочку **краткосрочную** и отправьте ровно ту же фразу.

- [ ] Ответ поплыл: агент не знает, о чём речь, и просит уточнить.

Верните галочку обратно.

**6.3. Рабочая память**

Заведите задачу `проба-слоёв`, перейдите в `execution`, запишите шаг
`ключ` = `выяснили: SRID 3857, слой организаций грузим первым`. Спросите:

```
Какой следующий шаг по текущей задаче?
```

- [ ] Ответ ссылается на записанное в рабочей памяти.
- [ ] В трейсе есть включённый блок с бейджем `рабочая`.

Снимите галочку **рабочую** и повторите вопрос.

- [ ] Агент отвечает общими словами: состояния задачи он больше не видит.

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| «ModuleNotFoundError: No module named 'flask'» | запущено системным python без зависимостей — активируйте venv |
| страница открылась, но кнопки ничего не делают | открыт старый экземпляр сервера на занятом порту: `ss -ltnp \| grep 5000` |
| «Не задан ключ API» | нет `.env` или в нём пустой `GROQ_API_KEY` |
| ответ долго не приходит | минутный лимит провайдера; клиент ждёт и повторяет сам, в консоли сервера видно «Лимит расхода, ждём N с» |
| долговременная память пуста | каталог `memory/` был удалён после первого запуска — перезапустите сервер, наполнение произойдёт заново |

После проверки можно вернуть прежнюю память:

```bash
rm -rf memory && mv memory-до-проверки memory
```
